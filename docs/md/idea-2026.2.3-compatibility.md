# IDEA 2026.2.3 升级与兼容性验证

2026-10-29 查询 JetBrains [正式发布接口](https://data.services.jetbrains.com/products/releases?code=IIU&latest=true&type=release)，最新稳定版为 IntelliJ IDEA 2026.2.3，构建号 `262.10968.63`。构建使用对应 Community SDK 及匹配的 Scala 插件 2026.2.21。

[平台要求](https://plugins.jetbrains.com/docs/intellij/build-number-ranges.html#platform-versions)指定 Java 25；SDK 中的 `AnAction.class` 也使用 class-file version 69。开发说明和 CI 已同步切换到 JDK 25。插件元数据限定 262.x，不继续声明对 261.x 的安装兼容性。

## 适配内容

- 将默认 SDK 和独立兼容性脚本的默认目标更新为 `262.10968.63`，保留 `IDEA_BUILD` / `IDE_HOME` 显式覆盖。
- 补入 SDK 拆分后的 `intellij.testRunner.plugin` 编译依赖，解决 Scala API 引用的 `SMTRunnerTestTreeViewProvider.CustomizedDurationProvider` 无法解析问题；不将 IDE 模块打包进插件。
- 旧版 `SbtShellCommunication.command` / `listenerAggregator` 已不可用。输出查询改为 `SbtShellCommandSubmitter.runAndCollectOutput`；DOT 任务使用带事件处理器的 `SbtShellCommandRequest`。命令 future 到达完成边界后再处理结果，保留首次错误，区分缺失命令、普通错误、交互错误及进程终止，继续使用原有后台提交、超时和取消检查。
- Gradle 兼容包装器通过 `super.actionPerformed` 执行平台模板，再由已有 hook 委托构建系统与选中状态，消除直接调用 `OverrideOnly` 方法的违规。三个官方入口的可见性和两轮动态卸载/重载继续验证。
- 三个 Gradle 包装器分别通过公开构造器创建对应的官方 Action，去除 `ActionManagerImpl.getBaseAction`、内部实例化及 `ActionStub.initAction` 引用。Gradle 保持可选运行时依赖，禁用 Gradle 时不加载包装器。插件元数据使用公开的 `PluginDetailsService`，释放回调使用 `Disposer.register`。
- 导入模型测试改用后台智能读操作查询声明和更新动作；在编辑、Undo/Redo 后同样等待智能模式，避免索引过程中临时禁用动作造成测试误判。未移除生产动作的索引保护或放宽行为断言。

## 复现与边界

使用 JDK 25，在仓库根目录执行：

```sh
sbt clean check test psiTest gradleAnalyzerTest runPluginVerifier
PYTHONDONTWRITEBYTECODE=1 python3 tools/test-upload-plugin.py
python3 tools/test-sbt-workflows.py
python3 tools/upload-plugin.py --dry-run
```

IDE 结果位于 `target/smoke/results/`，Gradle 检查位于 `target/gradle-analyzer-compat/`，Verifier 报告位于 `target/verifier/offline-reports/`。生成文件不提交到仓库。

IDE 测试验证真实平台/Scala PSI、服务注册和 shell 请求事件处理；真实 sbt 命令夹具通过 CLI 执行。它们不替代在 IDEA 中完整启动 shell 并导入真实大项目的手工测试，也不代表已验证 Marketplace 安装、Android Studio 或其他平台分支。未执行实际上传。

## 元数据服务初始化回归修复

启动时不允许从 Scala object 的类初始化器获取 IDE 服务。`details` 从立即求值的 `val` 改为按需执行的 `def`，仅在更新检查或展示说明时获取 `PluginDetailsService`。新增无 IDE Application 的类初始化回归测试；修复前会在服务获取处中止，修复后插件对象与 ID 可正常初始化。现有 IDEA 测试继续验证启动检查及更新说明中的真实元数据读取。

依赖删除/排除预览使用 IDEA 原生 Diff，代码区遵循编辑器配色，弹窗外围遵循 UI 主题；二者可独立设置。新增默认浅色和 Darcula 深色下删除、排除共四种预览组合，验证左右编辑器的前景与背景均使用所选配色。插件调试实例的配置独立于日常 IDEA，可在“设置 → 编辑器 → 配色方案”中选择相同的深色方案。

本次回归修复验证：74 项单测、85 项 IDEA 检查通过；新增启动日志未出现服务初始化错误。Verifier 为 `Compatible`，19 处弃用、81 处实验性引用，内部 API 仍为 0。
